# Layered Prestige

Pecorella's Part III models prestige as a single loop. You play, you reset, the next run is faster, you reset again. The outermost variable is `prestige_count`; everything else is a function of it. The whole structure is one cycle, no matter how many times it repeats.

The post-2016 genre, when it stops at one loop, stops at one game. Antimatter Dimensions ladders four prestige layers — Infinity, Eternity, Reality, and Pelle's Doomed reality — each of which resets every layer below it and runs on its own currency, formula, and tempo. Synergism stacks five before the player runs out of letters: Prestige, Transcension, Reincarnation, Ascension, Singularity. Prestige Tree, the framework that codified the pattern, exposes layer composition as the entire surface area.

This page is about what changes when prestige stops being a loop and becomes a stack.

## A loop is a layer with no outside

Pecorella's model has two state variables that survive a reset:

- A prestige *currency* $P$ that grows monotonically across runs.
- A bonus shape $B(P)$ that the next run starts under.

Everything else — the in-run currency, the generators, the milestone counts — is reset to zero. The reset boundary is sharp: one moment you have $C(t)$ at its peak, the next moment $C = 0$ and $P$ is slightly larger. The point of the reset is to make $P$ go up.

A second-tier prestige is built by treating $P$ itself as the *in-run* currency of a layer above it. The math is a recursion. If layer 1 is Pecorella's loop, then layer 2 has:

- Its own in-run currency $P$ (that is, layer-1 prestige).
- Its own prestige currency $Q$.
- Its own bonus shape $B'(Q)$ that boosts layer-1's bonus shape.

When the player triggers a layer-2 reset, $Q$ gains $\Delta Q = g(P_{\max})$, then $P$ is reset to zero along with everything *layer 1* used to build it — generators, multipliers, in-run currency, milestones. The reset cascades downward: layer-2's reset implies a layer-1 reset implies whatever layer-1's reset cascade implies. The thing that survives is $Q$, plus the rules of the game itself.

This is the structural definition: **a prestige currency is at layer $k$ if it survives the reset of layer $k-1$.** That's the whole criterion. Whether the game labels the layer "Eternity" or "Ascension" or "Mythos" is decoration — what makes it a layer is that its reset wipes the layer below.

## The cascade rule, in code

The reset cascade is the load-bearing implementation detail of every layered prestige system. It's the rule that says "when layer 2 resets, layer 1's stash goes too, but layer 2's stash doesn't." Skipping it produces save files where layer-1 currency drifts higher and higher across layer-2 resets and the layered structure silently collapses into one fat single-tier loop.

Antimatter Dimensions implements this as one long sequence inside `finishProcessReality`. When the player triggers a Reality reset (layer 3), the function explicitly zeroes everything layer 2 owned:

<Cite repo="AntimatterDimensionsSourceCode" path="src/core/reality.js" line="623-650" />

```js
Currency.infinities.reset();
Currency.infinitiesBanked.reset();
// ...
Currency.infinityPower.reset();
Currency.timeShards.reset();
Replicanti.reset(true);

Currency.eternityPoints.reset();

EternityUpgrade.epMult.reset();
if (!PelleUpgrade.eternitiesNoReset.canBeApplied) Currency.eternities.reset();
```

The Reality reset zeroes Infinity Points (layer 1), Eternity Points (layer 2), and *almost* every per-Eternity counter the game tracks. What it doesn't zero is the layer-3 currency itself (Reality Machines), the glyphs the Reality created, and a small set of "legacy" carry-overs guarded by `PelleUpgrade.eternitiesNoReset` and other late-game upgrades whose explicit purpose is to *exempt* a downstream resource from the cascade.

Those exemption flags are the second load-bearing detail. A layered prestige system isn't just "reset cascades downward" — it's "reset cascades downward *unless explicitly exempted*." The exemptions are what late-game upgrade trees buy: the right to stop losing something. The genre's vocabulary of "preserves," "keeps," "no-reset" — `eternitiesNoReset`, `keepEternityUpgrades`, `keepEternityChallenges`, `dilationUpgradesNoReset` — is a vocabulary of cascade-exemption flags. Each one is a small hole punched in the reset wall.

Prestige Tree formalizes this as a row-by-row reset. Its `doReset(layer)` calls `rowReset(x, layer)` for every row `x` from `tmp[layer].row` down to 0, walking the layer DAG bottom-up:

<Cite repo="Prestige-Tree" path="js/game.js" line="225-231" />

```js
prevOnReset = {...player} // Deep Copy
player.points = (row == 0 ? new Decimal(0) : getStartPoints())

for (let x = row; x >= 0; x--) rowReset(x, layer)
rowReset("side", layer)
```

The `rowReset` invocations are filtered by per-layer milestones — Prestige Tree's analogue to AD's exemption flags — declared inline next to each `addLayer` definition. The cascade rule and the exemption rule live in the same configuration object.

## Each layer rewrites the prior loop's math

The deeper move — and the thing that distinguishes layered prestige from a stack of identical loops — is that *each layer's formula operates on a different feature of the layer below*.

Pecorella's prestige currency at time $t$ is some $\sqrt{C_L(t) / D}$ — square root of lifetime production. That formula could be reused at layer 2 (square root of layer-1 lifetime), and some games do exactly that. But the canonical post-2016 move is to use a *qualitatively different* formula at each layer, so the math the player optimizes against changes shape every time they ascend.

Antimatter Dimensions:

<Cite repo="AntimatterDimensionsSourceCode" path="src/game.js" line="89-103" />

```js
let ip = player.break
  ? Decimal.pow10(player.records.thisInfinity.maxAM.log10() / div - 0.75)
  : new Decimal(308 / div);
```

The Infinity Point formula reads: $\text{IP} = 10^{\log_{10}(\text{maxAM})/308 - 0.75}$ — that is, IP is a [power law](https://en.wikipedia.org/wiki/Power_law) of antimatter with exponent $1/308 \approx 0.0032$. Because the divisor is 308, it takes a full decade of antimatter past $10^{308}$ — the JavaScript Number ceiling, deliberately echoed — to gain one decade of IP. The formula is the cap; it converts a loose number into a tight one.

<Cite repo="AntimatterDimensionsSourceCode" path="src/game.js" line="138-140" />

```js
let ep = DC.D5.pow(player.records.thisEternity.maxIP.plus(
  gainedInfinityPoints()).log10() / (308 - PelleRifts.recursion.effectValue.toNumber()) - 0.7).times(totalEPMult());
```

Eternity Points: $\text{EP} = 5^{\log_{10}(\text{maxIP})/308 - 0.7}$. Same divisor — 308 — but the base is now 5 instead of 10. The compression is roughly seven times steeper than IP's: a decade of IP gives $\log_{10}(5) \approx 0.7$ decades of EP. Stacking IP's compression on top of EP's compression, you need ten decades of antimatter to gain one decade of IP, and seventy decades of antimatter to gain one decade of EP. The doubled compression is what makes the layer-2 ascent feel like its own game rather than a faster version of layer 1.

<Cite repo="AntimatterDimensionsSourceCode" path="src/core/machines.js" line="19-29" />

```js
let log10FinalEP = player.records.thisReality.maxEP.plus(gainedEternityPoints()).log10();
if (!PlayerProgress.realityUnlocked()) {
  if (log10FinalEP > 8000) log10FinalEP = 8000;
  if (log10FinalEP > 6000) log10FinalEP -= (log10FinalEP - 6000) * 0.75;
}
let rmGain = DC.E3.pow(log10FinalEP / 4000 - 1);
```

Reality Machines: $\text{RM} = 1000^{\log_{10}(\text{maxEP})/4000 - 1}$. The base is 1000 (ten times steeper than EP) and the divisor jumps from 308 to 4000 (thirteen times shallower than EP). The shape is still a log-of-log-of-log power law, but now with a *different* constant pair, plus a discontinuous softcap that interrupts the curve below the 8000-decade threshold. None of the formulas is a copy of the one below it. Each one is a different design problem — different breakeven, different prestige cadence, different optimal-reset math.

The general pattern: every layer's formula is some tightening of "the most recent thing the layer below cares about." Layer 1 cares about in-run antimatter; layer 2 cares about per-run IP (max IP within this Eternity); layer 3 cares about per-run EP (max EP within this Reality). The layered structure isn't "prestige currency 1, prestige currency 2, prestige currency 3" stacked vertically — it's a chain of *different* compressions, each operating on the per-layer-below maximum, each with its own constants the designer picked to set the layer's tempo.

## Layer thinning

The visible consequence on the time axis is that each layer takes much longer to climb than the one below it. With a power-law formula like AD's, the slope on log-log axes is the exponent — and stacked layers multiply exponents.

<LayeredPrestigeCascade client:visible />

The square-root preset reproduces Pecorella's classic: layer 1 is $\sqrt{t}$, slope 0.5. Stack it: layer 2 is $\sqrt{\sqrt{t}} = t^{1/4}$, slope 0.25. Layer 5 is $t^{1/32}$, slope 0.03 — almost flat. After enough layers, even five extra decades of total game time barely move the highest layer's currency.

The AD-style preset (α = 1/308) is a different story. The first layer is so flat that after $10^{20}$ in-run currency you've gained roughly $10^{20/308} \approx 10^{0.065}$ of layer-1 currency — a hair more than 1. The second layer flattens that *again*. Real games soften this with multiplicative bonuses, milestone multipliers, and per-layer prestige-multiplier upgrades that act on the layer's gain rate without changing its shape — they shift the curve up, but they don't change the slope. The slope is the design-locked compression. The bonuses are the dial the designer turns to make ascent times feel right.

The shape this enables is what the post-2016 genre actually wanted from prestige: a pacing tool where each layer takes *more total real-world time* than the one below, regardless of player skill. With single-tier prestige you can't make a player spend longer at the wall — they get better, the wall doesn't move. With layered prestige, the wall is built into the formula. The number of times you can fit "$\log_{10}$ followed by divide-by-308" into a layer cap *is* how many layers the game has.

## The DAG, not the stack

The framing so far has been linear: layer 0 → layer 1 → layer 2. Real games are messier — Prestige Tree's row structure is a [directed acyclic graph](https://en.wikipedia.org/wiki/Directed_acyclic_graph), not a chain. Each layer registers itself with a `row` and a list of `branches`, and the visual tree is laid out by row depth with branches drawn between layers that share resources.

<Cite repo="Prestige-Tree" path="js/layers.js" line="281-291" />

```js
addLayer("b", {
  name: "boosters",
  symbol: "B",
  position: 0,
  color: "#6e64c4",
  requires() { return new Decimal(200).times((player.b.unlockOrder&&!player.b.unlocked)?5000:1) },
  resource: "boosters",
  baseResource: "points",
  baseAmount() {return player.points},
  type: "static",
  branches: ["p"],
```

The `branches: ["p"]` declaration says: boosters branch off prestige. They sit at row 1 (one row above prestige's row 0), they draw a visual edge to prestige, and — critically — when boosters reset, they reset the prestige row beneath them. The branches list is not just decoration; it's the cascade graph. `doReset` walks rows from highest-resetting downward, so a row-2 reset cascades through row 1 and row 0, but only along the connections the layer registry declared.

This is the move that makes layered prestige composable as a system rather than a one-off design. Adding a new layer in Prestige Tree is one `addLayer` call: a row number, a base resource, a formula type (`"normal"` or `"static"` — sub-linear vs. step-cost cost curves), an exponent, and a list of branches. The framework handles the cascade. The framework handles the unlock conditions. The framework draws the tree. What the designer writes is the formula and the milestone effects — which is to say, the *math the player will optimize against*, isolated from the bookkeeping.

The Profectus toolkit, Prestige Tree's successor, generalizes the row-and-branch graph further: layers can be DAG-acyclic with multiple parents, branches can be conditional, and the per-layer formula type expands into a full closed-form DSL. The lineage is the same: layered prestige as a configuration, not an implementation.

## What this enabled

**Late-game content as layers, not levels.** A single-tier prestige game has one mid-game and one late-game; once the player saturates the prestige multiplier, there's nowhere to go. A layered prestige game can introduce content with each layer — Antimatter Dimensions's Time Studies (layer 2), Glyphs (layer 3), Imaginary Machines (layer 3+). The layer boundary is a content boundary in the same way a level boundary is in an RPG. Players cite "the new mechanics behind prestige tier 4" the way RPG players cite "the spells you unlock at level 30."

**Optimization as a cross-layer portfolio.** Single-tier prestige asks one question: when do I prestige? Layered prestige asks a portfolio of questions — when do I prestige *at this layer*, when do I let layer-2 currency accumulate before triggering layer 3, which layer's upgrade tree do I push first. Synergism's player community has documented optimization strategies for trading off between Mythos (layer 2) and Particles (layer 3) gain rates that are orders of magnitude more elaborate than any single-tier optimization. The optimization surface is itself a content surface.

**A hard ceiling on the in-run scale.** AD's first prestige (the Big Crunch) fires when antimatter reaches $2^{1024}$ — exactly the JavaScript Number ceiling. The game keeps running on `Decimal` (covered on the Big Numbers page), but the *in-run* currency stays bounded by design at every layer. Antimatter never goes past $\sim 10^{308}$ in a single Infinity. IP never goes past whatever the layer-2 cap is in a single Eternity. The number on the screen at any layer below the topmost is bounded; only the topmost layer's currency is allowed to grow without bound. This is the genre's working answer to "how do you keep a game legible when the math is unbounded": you bound every layer except one, and you only show the unbounded layer in its top position.

## What this costs

**Save shape complexity.** Each layer needs its own per-layer maxima (`thisInfinity.maxAM`, `thisEternity.maxIP`, `thisReality.maxEP` in AD), its own counters, its own milestone bits, its own exemption flags. AD's player object at the Reality layer contains nested records for `bestEternity`, `bestInfinity`, `bestReality`, each with their own time-best, count-best, currency-best fields. Save migration across game updates becomes a matter of versioning each layer separately. The genre's working answer is `JSON.stringify` with explicit per-field rehydration; there is no schema.

**Comprehension cliff.** The first layer is "score." The second layer is "score for your scores." The third is "score for your score-scores." Players bounce off the genre at the second-layer transition more than at any other point. AD's Eternity tutorial is the longest tutorial in the game, and it still tries to explain a four-line formula by analogy. The cliff is real and well-documented; the genre's working answer is to slow the first layer-2 ascent enough that the player has time to reframe before they need to optimize.

**Balance entanglement.** Each layer's formula has constants the designer chose to set its tempo. Those constants interact: making the IP formula 10% steeper makes the EP formula effectively 10% steeper too, since EP runs on the integral of IP. AD's `308`s and `0.75`s and `4000`s are all hand-tuned numbers that produce the current ascent times under the current set of upgrade trees, glyph effects, and challenge multipliers. Touching one in isolation is a respec across every layer above it. This is why layered-prestige games tend to ship constants and never change them — the maintenance cost of rebalancing across layers is far worse than living with a slightly off-target formula. AD's `308` has not moved since 2016; AD's `0.75` has not moved since 2016. They are load-bearing constants.

**No reverse gear.** A single-tier prestige system can be tuned by adjusting the prestige formula. A layered prestige system can be tuned, but the layers are nested: changing layer 2's formula reshapes layer 3's input, which reshapes layer 3's output. Designers learn to draft new content as *new layers* rather than as adjustments to existing layers. AD's expansions — Reality, Imaginary, Pelle — are all *upward*. Once a layer ships, its math is frozen, because every layer above it has been tuned against the version that shipped.

## What this site uses

`open-loop-engine` ships layered prestige as a configuration shape, not a fixed mechanic. A reset declaration takes a target — the highest layer this reset wipes — plus per-currency exemption flags. Layer registration mirrors Prestige Tree's `addLayer`: a tier number, a base resource, a formula, and a list of branches. The cascade walks rows the way Prestige Tree does. The vocabulary maps onto the research: tier structure, reset scope, persistence type, formula family, timing mode — five orthogonal dimensions, each declarable per layer.

The reason to declare it as a configuration rather than implement it as a feature is exactly the entanglement above. A game that stacks five layers without engine support will end up with five hand-rolled cascade routines, five hand-rolled save-shape extensions, and five hand-rolled milestone-exemption checks. The cost compounds layer-by-layer. The engine eats the bookkeeping so the per-game work is just the formula and the cadence — the parts that actually matter to the design.
